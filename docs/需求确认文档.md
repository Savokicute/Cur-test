## 🎯 产品目标

### 解决什么问题
1. **热榜数据分散**：各平台热榜需要分别查看，效率低
2. **爬取正文内容**：
3. **临时界面简陋**：现有 Web 界面只是测试用，功能和体验都不好
4. **缺少事件聚合**：相似热点没有聚合展示，不便于发现热点事件
5. **缺少 AI 辅助**：没有 AI 摘要、选题建议等功能

### 为什么做
- 提升热点资讯获取效率
- 一站式查看各平台热点
- 为内容创作提供素材和选题参考
- 把现有的零散功能（TrendRadar + crawl4ai）整合到一个统一的 Web 平台

### 第一版核心目标
1. **整合现有功能**：把热榜获取和正文爬取整合到一个新的 Web 平台
2. **完善 UI 体验**：重新设计界面，提升使用体验
3. **原型验证**：把 PRD 中的所有页面都先做出来（用 Mock 数据），验证产品设计

## 📖 核心使用场景

### 场景 1：查看最新热点
**什么情况下用**：想快速了解各平台最新热点

**主要任务**：
1. 打开热点总览页
2. 浏览各平台热点卡片
3. 查看热点详情和相关新闻
4. 点击进入正文查看

**完整使用路径**：
```
访问平台 → 热点总览页 → 浏览热点卡片 → 点击热点查看详情 → 点击查看正文 → 阅读正文
```

---

### 场景 2：查找素材
**什么情况下用**：需要找某个主题的素材

**主要任务**：
1. 进入素材中心
2. 按来源、时间、事件筛选
3. 查看素材详情
4. 收藏素材（后续版本）

**完整使用路径**：
```
访问平台 → 素材中心页 → 筛选条件 → 浏览素材列表 → 点击查看详情 → 收藏（可选）
```

---

### 场景 3：管理采集源
**什么情况下用**：需要配置采集哪些平台、哪些网站

**主要任务**：
1. 进入采集源配置页
2. 配置热榜源（开关、权重）
3. 配置网站源（URL 模板、CSS 选择器）
4. 配置抓取参数

**完整使用路径**：
```
访问平台 → 采集源配置页 → 配置热榜源 → 配置网站源 → 配置抓取参数 → 保存
```

## 🔧 核心技术模块详解

### 1. TrendRadar —— 完整功能说明

#### 1.1 项目结构
```
trendRadar/
├── trendradar/
│   ├── core/              # 核心模块
│   │   ├── analyzer.py    # 热点分析（关键词分组、权重计算）
│   │   ├── config.py      # 配置加载
│   │   ├── data.py        # 数据结构定义
│   │   ├── frequency.py   # 关键词匹配逻辑
│   │   ├── loader.py      # 数据加载
│   │   └── scheduler.py   # 调度系统
│   ├── crawler/           # 爬虫模块
│   │   ├── fetcher.py     # 热榜抓取
│   │   └── rss/           # RSS 抓取
│   ├── ai/                # AI 模块
│   │   ├── analyzer.py    # AI 分析
│   │   ├── filter.py      # AI 智能筛选
│   │   └── translator.py  # AI 翻译
│   ├── notification/      # 通知模块
│   │   ├── dispatcher.py  # 通知分发
│   │   ├── senders.py     # 各渠道发送器
│   │   └── renderer.py    # 渲染器
│   ├── storage/           # 存储模块
│   │   ├── manager.py     # 存储管理器
│   │   ├── local.py       # 本地存储
│   │   └── remote.py      # 远程云存储
│   └── report/            # 报告生成
│       ├── generator.py   # 报告生成器
│       └── html.py        # HTML 报告
```

#### 1.2 核心配置（config.yaml）

##### 数据源配置
- **热榜平台**：可配置启用的平台列表（35+ 可选）
  - 例如：微博、知乎、今日头条、百度、B站、澎湃新闻、财联社等
  - 支持自定义显示名称
- **RSS 订阅**：可配置 RSS 源列表
  - 支持新鲜度过滤（按文章发布时间）
  - 每个源可单独配置保留天数

##### 筛选策略
- **关键词模式**：通过 `frequency_words.txt` 配置
  - 支持普通词、必须词（`+`）、过滤词（`!`）
  - 支持正则表达式（`/pattern/`）
  - 支持组别名（`[组名]`）
  - 支持显示名称（`=>` 别名）
  - 支持最大显示数量（`@数字`）
  - 支持全局过滤（`[GLOBAL_FILTER]`）

- **AI 智能筛选模式**：通过 `ai_interests.txt` 配置
  - 用自然语言描述兴趣方向
  - AI 自动提取标签并打分
  - 支持阈值控制推送精度
  - 支持批量处理和智能重分类

##### 报告模式
- **daily**：当日汇总（信息最全，重复最多）
- **current**：当前榜单（适合盯热度）
- **incremental**：仅新增（最少打扰）
- **display_mode**：keyword（按关键词）或 platform（按平台）

##### AI 分析功能
- 基于 LiteLLM 支持 100+ AI 提供商
- 可配置模型、API Key、Base URL
- 支持 AI 分析、AI 翻译、AI 筛选
- 支持自定义提示词模板
- 支持排名时间线分析

##### 通知渠道
- 企业微信
- 个人微信
- 钉钉
- Telegram
- 邮件
- ntfy
- Bark
- Slack
- 通用 Webhook

##### 存储配置
- 本地 SQLite
- 远程云存储（S3 兼容：Cloudflare R2、阿里云 OSS、腾讯云 COS 等）
- 数据保留策略（天数）

##### 调度系统
- 预设模板：always_on、morning_evening、office_hours、night_owl
- 可自定义 timeline.yaml
- 每个时段可独立配置：推送/分析模式、筛选策略、兴趣文件

#### 1.3 核心数据结构（SQLite）
- `news_items`：热榜新闻（标题、平台、排名、URL、时间、热度等）
- `platforms`：平台信息
- `rank_history`：排名变化历史
- `crawl_records`：抓取记录
- `rss_items`：RSS 文章
- `ai_filter_results`：AI 筛选结果

### 2. hot_content_bridge —— 完整功能说明

#### 2.1 项目结构
```
hot_content_bridge/
├── article_crawler.py      # 正文爬虫
├── platform_rules_loader.py  # 平台规则加载器
├── storage.py              # 存储管理
├── hotlist_reader.py       # 热榜数据读取
├── cli.py                  # 命令行工具
├── config.yaml             # 配置文件
├── platform_rules/         # 平台规则目录
│   ├── _default.yaml       # 默认规则
│   ├── weibo.yaml
│   ├── zhihu.yaml
│   ├── toutiao.yaml
│   └── ... (11 个平台)
└── tests/                  # 测试
```

#### 2.2 核心配置（config.yaml）

##### TrendRadar 路径
- `root`：TrendRadar 项目根目录
- `config_yaml`：TrendRadar 配置文件路径

##### 正文爬取配置
- `max_urls_per_run`：每次运行最多爬取条数
- `concurrency`：并发数
- `per_domain_min_delay_s` / `per_domain_max_delay_s`：域名级延迟范围
- `request_timeout_ms`：请求超时
- `max_retries`：重试次数
- `top_rank_only`：仅爬取前 N 名
- `skip_domains`：跳过的域名列表

##### 内容提取策略
- `content_filter`：bm25（按标题相关性选段）或 pruning（密度剪枝）
- `bm25_threshold`：BM25 阈值
- `pruning_threshold`：剪枝阈值
- `word_count_threshold`：最小词数阈值

##### 浏览器配置
- `delay_before_return_html`：页面加载后等待时间
- `wait_until`：等待事件（domcontentloaded、networkidle 等）
- `remove_forms`：是否移除表单
- `exclude_external_links`：是否排除外链
- `exclude_social_media_links`：是否排除社交链接
- `markdown_ignore_links`：Markdown 中是否忽略链接
- `post_strip_boilerplate`：是否去除 boilerplate

#### 2.3 平台规则系统
每个平台可配置：
- `platform_id`：平台 ID
- `display_name`：显示名称
- `hosts`：匹配的域名列表
- `enabled`：是否启用
- `css_selector`：CSS 选择器
- `target_elements`：多个目标元素选择器
- `primary_target`：主要目标元素
- `content_filter`：内容过滤策略
- `delay_before_return_html`：等待时间
- `wait_until`：等待事件

#### 2.4 命令行工具（CLI）
```bash
# 仅抓取热榜（跳过完整 trendRadar 流程）
python -m hot_content_bridge fetch-hotlist-only

# 运行完整 trendRadar
python -m hot_content_bridge sync-hotlist

# 爬取正文
python -m hot_content_bridge crawl-articles --limit 50

# 完整流水线（热榜 + 正文）
python -m hot_content_bridge run-pipeline --quick-hotlist --limit 50

# 列出平台规则
python -m hot_content_bridge list-platform-rules

# 启动临时 Web 服务器
python -m hot_content_bridge serve-web --port 8765
```

#### 2.5 数据存储（SQLite）
- `article_contents`：正文内容表
  - `id`：主键
  - `url`：原始 URL
  - `url_norm`：标准化 URL（去重用）
  - `platform_id`：平台 ID
  - `status`：状态（pending/success/failed）
  - `markdown`：正文 Markdown
  - `extracted_title`：提取的标题
  - `content_sha256`：内容哈希（去重用）
  - `crawl_time`：抓取时间
  - `error_msg`：错误信息

### 3. crawl4ai —— 功能模块

#### 3.1 核心特性
- **浏览器自动化**：基于 Playwright，支持动态页面渲染
- **智能内容提取**：
  - BM25 算法：按标题相关性选段
  - Pruning 算法：密度树剪枝
- **Markdown 生成**：自动将 HTML 转换为 Markdown
- **缓存机制**：避免重复抓取
- **内容后处理**：
  - 去除 boilerplate（页头页脚等模板内容）
  - 去重
  - 链接处理
- **多策略支持**：可同时配置多个目标元素选择器，自动降级

- **集成**：
  - 复用 `hot_content_bridge` 模块进行正文爬取
  - 复用 `trendRadar` 模块读取热榜数据

- **框架**：React + Vite
- **UI 组件库**：Ant Design
  - 企业级，设计成熟
  - 组件丰富，避免 AI 味
- **样式方案**：Tailwind CSS（可选）
- **状态管理**：React Query（可选，看需求）

### 4. Mock 数据方案
- **未完成的页面**：使用 Mock 数据填充
- **目的**：提前看到完整产品效果，方便调整 UI 设计

### 模块关系说明
1. **crawl4ai**：底层浏览器自动化爬虫库，被 hot_content_bridge 使用
2. **hot_content_bridge**：
   - 使用 TrendRadar 读取热榜数据
   - 使用 crawl4ai 爬取正文内容
   - 提供 CLI 工具和 Web 服务器
3. **web/backend**：
   - 调用 hot_content_bridge 的功能
   - 读取 TrendRadar 的数据
   - 为前端提供 API
4. **web/frontend**：
   - 对接后端 API
   - 展示热榜和正文内容
