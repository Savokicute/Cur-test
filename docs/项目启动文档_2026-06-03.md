## 一、项目概述

热点发现平台是一个基于 **TrendRadar**（热榜采集）、**crawl4ai**（正文爬取）和 **we-mp-rss**（微信公众号采集）的综合内容发现平台。整合三大采集源，提供统一的内容发现、素材获取和订阅管理工具。

### 核心架构

```
scripts/start_platform.py (一键启动)
    |
    +-- hot-content-bridge daemon (热榜 + 正文爬取守护进程)
    |      |-- fetch-hotlist-only --> trendRadar/output/news/{date}.db
    |      +-- crawl-articles -----> article_contents (同库, crawl4ai/Playwright)
    |
    +-- we-mp-rss main.py -job True (微信公众号, 端口 8001)
```

### 技术栈

| 组件 | 技术 | 版本要求 |
|------|------|----------|
| Python | 3.12+ | 3.12.x 或 3.13.x |
| 包管理器 | uv | 0.4.x+ |
| 前端框架 | React + Vite + Ant Design 5 | — |
| Node.js | LTS 20 | 20.x |
| 浏览器引擎 | Playwright Chromium | 与 lock 一致 |
| 数据库 | SQLite (多库) | — |

## 二、标准启动流程

### 第 1 步：环境自检（首次必须）

```bash
# 在项目根目录执行
uv run python scripts/verify_environment.py
```

**预期输出**: 所有检查项显示 `[通过]`，最终 `[成功] 所有检查通过!`

**检查项清单**:
| 检查项 | 说明 |
|--------|------|
| Python 版本 | >= 3.12 |
| uv 包管理器 | 已安装 |
| 依赖锁定文件 | `uv.lock` 存在且与 pyproject.toml 一致 |
| Editable 子包 | trendradar、crawl4ai、hot_content_bridge 可 import |
| Playwright + 浏览器 | Chromium 已安装 |
| Node.js 版本 | 推荐 20.x |
| we-mp-rss 集成 | 可由 start_platform.py 启动 |

### 第 2 步：安装依赖（首次或依赖变更后）

```bash
# Python 依赖（含 editable 子包）
uv sync --group dev

# Playwright 浏览器（正文爬取必需）
uv run playwright install chromium

# 前端依赖（展示层开发时需要）
cd web/frontend && npm ci && cd ../..
```

### 第 3 步：启动采集层（核心）

```bash
# ===== 快速模式（默认，仅热榜+正文）=====

# 方式 A: 单轮测试 — 仅热榜 API 入库 + 正文爬取，不含 AI 分析
uv run python scripts/start_platform.py --once --no-wemp

# 方式 B: 守护进程模式（生产/常驻）
uv run python scripts/start_platform.py                    # 含公众号
uv run python scripts/start_platform.py --no-wemp           # 不含公众号

# ===== 完整模式（含 AI 分析/筛选/推送/报告）=====

# 方式 C: 单轮完整 TrendRadar — 热榜 + AI 筛选 + AI 分析 + 推送通知 + HTML 报告 + 正文爬取
uv run python scripts/start_platform.py --once --full --no-wemp

# 方式 D: 守护进程完整模式 — 每 30 分钟执行一次完整 TrendRadar 全流程
uv run python scripts/start_platform.py --full               # 含公众号
uv run python scripts/start_platform.py --full --no-wemp      # 不含公众号
```

**两种模式对比**:

| | **快速模式** (`--once`, 默认) | **完整模式** (`--once --full`) |
|---|---|---|
| **热榜采集** | `fetch-hotlist-only` (API 直取) | `python -m trendradar` (全流程) |
| **AI 智能筛选** | 无 | 有 (按 `filter.method=ai` 分类) |
| **AI 深度分析** | 无 | 有 (趋势分析、热点解读) |
| **推送通知** | 无 | 有 (钉钉/飞书/Bark 等) |
| **HTML 报告** | 无 | 有 (`output/html/`) |
| **正文爬取** | 有 | 有 (crawl4ai) |
| **耗时** | ~3-5 分钟 | ~10-20 分钟 (取决于 AI 调用) |
| **受调度限制** | 否 (始终采集) | 是 (受 `schedule` 时间窗影响) |

> **注意**: 完整模式受 TrendRadar 的 `schedule` 配置控制。若当前时间不在调度时间窗内，可能跳过采集。如需强制执行，可临时将 `trendRadar/config/config.yaml` 中 `schedule.enabled` 设为 `false`。

**成功标志**:
- 日志出现 `Hot list: OK`
- 日志出现 `Article crawl: crawled=...`
- 完整模式额外出现: AI 分析日志、推送发送记录
- `trendRadar/output/news/{今日日期}.db` 文件存在且大小 > 0

### 第 4 步：启动 Web 层（可选，阶段〇-B 完成后）

```bash
# 后端 API (端口 8000)
uv run uvicorn app.main:app --reload

# 前端 (端口 5173)
cd web/frontend && npm run dev
```

**反模式警告**: 仅启动前端/后端而不启动 daemon → 只能看到旧日库或空数据。

## 五、常用运维命令

```bash
# === 采集层 — 快速模式（仅热榜+正文）===

uv run python scripts/start_platform.py --once --full --no-wemp

# 等效 CLI 命令（直接调用）

# === 守护进程 ===

# 快速守护进程（每30分钟：热榜 API + 正文）

cd web/frontend && npm run dev

uv run hot-content-bridge serve-web
```

## 七、已知问题与注意事项

1. **凤凰网反爬**: 部分 ifeng 页面会触发 60s 超时，属正常现象。可通过代理(`use_proxy: true`)改善。
2. **空 markdown 重试**: 澎湃新闻部分页面首次提取为空时会自动重试 scopeless 模式。
3. **platform_id 为空**: 部分历史数据的 platform_id 未填充，不影响正文关联（通过 news_item_id 关联）。
4. **时区注意**: 所有时间以 `Asia/Shanghai` 为准，数据库存储 UTC 时间。
